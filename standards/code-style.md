# Code Style

This standard is normative for generated projects unless a local project standard overrides it.

Key requirements:
- Define acceptance criteria before implementation.
- Keep scope bounded; no unrelated refactoring.
- Run targeted checks during development and full gates for release candidates.
- Update documentation when behavior, architecture, data formats, configuration, or release process changes.
- Evidence report must list exact commands, exit codes, skipped checks, and residual risks.
